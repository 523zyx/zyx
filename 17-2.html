fetch 请求的三步走

async / await

原生 fetch 返回的是一个 Promise，用 async/await 写起来像同步代码；注意 fetch 只有网络断了才 reject，404/500 不会自动报错，要自己判断 res.ok。

1

发送请求

fetch(url) 发出 GET 请求，拿到一个 Response 对象（此时还只是响应头）。

2

检查状态

res.ok 为 true 才算成功；也可以用 res.status 判断 200。

3

解析数据

res.json() 把响应体读成 JS 对象，这一步也是异步的。

async function getDog() { try { const res = await fetch("https://dog.ceo/api/breeds/image/random"); if (!res.ok) throw new Error("HTTP " + res.status); // 404/500 要自己判断 const data = await res.json(); // { message, status } console.log(data.message); // 图片地址 } catch (err) { console.log("请求失败：" + err.message); // 断网 / 超时 / 跨域 } }
接口只负责"给数据"，页面负责"把数据摆好看" —— 这就是前后端分离的雏形。
