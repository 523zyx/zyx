JSON 数据格式

JSON 是"写给程序看的文本格式"——它长得像 JS 对象，但规矩更严格。点按钮试试序列化和解析。

JSON 长什么样

JSON

JSON（JavaScript Object Notation）用花括号装一组 "键": 值，用方括号装一串值。键名一定是双引号包裹的字符串。

{ "name": "周雨欣", "age": 20, "vip": true, "major": null, "scores": [92, 88] }
键 key 字符串 数字 布尔 null

JSON 只认这六种值

types

JSON 是跨语言的数据格式，所以值类型被压缩到最小集合，没有函数、没有 undefined、没有日期对象。

"字符串" // 双引号包裹 2026 // 数字，不带引号 true / false // 布尔，小写 null // 空值 [...] // 数组 array {...} // 对象 object
不支持：undefined / 函数 / NaN / 注释

JSON 的语法红线：写成这样才合法

syntax

JSON 比 JS 对象严格得多，下面五条踩中任何一条，JSON.parse() 就会直接报错。

✅ 键名必须是双引号字符串 "name"；name / 'name' 都不行
✅ 字符串也必须是双引号 "前端"；'前端' 是单引号，不合法
✅ 最后一个成员后面不能有逗号；"age": 20,} 会报错
✅ 不能写注释；// 说明 在 JSON 里不存在
✅ 值只能是字符串、数字、布尔、null、数组、对象；function(){} / undefined 不合法

序列化：JSON.stringify()

stringify

把 对象 / 数组 变成 JSON 字符串，才能写进文件、发到服务器、存进 localStorage。

注意：undefined 和函数会在序列化时被悄悄删掉。

解析：JSON.parse()

parse

把 JSON 字符串还原成 真正的 JS 对象，之后就能用点语法取值了。格式错误会被 try...catch 抓住。

JS 对象 ≠ JSON

compare

JSON 是字符串，JS 对象是内存里的数据。前者只能传输和存储，后者才能直接操作。

对比项 JS 对象 JSON 文本
键名引号 可省略 必须双引号
字符串引号 单 / 双 / 反引号 只能双引号
函数 / undefined 可以有 不允许
注释 可以写 不允许
末尾逗号 允许（部分引擎） 绝对不行
用途 代码里操作数据 传输 / 存储
